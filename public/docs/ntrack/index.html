Overview

ntrack is a lightweight system-tray agent that monitors which applications and browser tabs are active on a desktop and periodically sends a daily summary to a nwork backend. It is designed to run silently in the background with no user interaction required after initial setup.

ℹ️

ntrack reports to nwork — an HR backend service. You must have a running nwork instance and an API key generated from it before ntrack can send data.

What ntrack tracks per day:

  • Total active and idle time (minutes)
  • Per-app usage (app name + browser domain, minutes)
  • Hourly breakdown of app usage
  • Session intervals (app, tab, start, end)

Requirements

RequirementNotes
Python 3.11+Only needed when running from source or building
macOS, Windows, or LinuxAll three platforms are supported
nwork backendRunning and reachable on the network
API keyGenerated from nwork web app under API Keys

On macOS, ntrack requires Accessibility permission to detect the active window. You will be prompted on first launch — grant it in System Settings → Privacy & Security → Accessibility.

Backend Setup

Before installing ntrack, make sure the nwork backend is running and you have an API key.

1. Start the nwork backend

# From the nwork-server directory
docker compose up -d          # Start PostgreSQL
./mvnw spring-boot:run        # Runs on http://localhost:8765

2. Generate an API Key

  1. Log in to the nwork web app as the employee who will run ntrack.

  2. Navigate to Profile → API Keys and click Generate Key.

  3. Copy the key — it will only be shown once.

⚠️

The API key authenticates as that specific employee. Each machine running ntrack should use the API key of the employee who works on it.

Installing ntrack

Option A — Download a pre-built binary

Download the latest release for your platform from the GitHub Releases page.

PlatformFileLocation after install
macOSntrack.dmgDrag ntrack.app to /Applications
Windowsntrack-setup.exeInstalls to %LOCALAPPDATA%\ntrack
⚠️

macOS Gatekeeper: If the app is blocked, right-click → Open, or run: xattr -cr /Applications/ntrack.app

Option B — Run from source

git clone https://github.com/nen02/ntrack-app.git
cd ntrack-app

# Create virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Run
python main.py

Configuration

On first launch, ntrack starts in a disconnected state. Open the tray icon and go to Settings to enter:

  • API URL — base URL of your nwork backend (e.g. http://192.168.1.10:8765)
  • API Key — the key generated in the nwork web app

Config is saved to a persistent directory that survives app updates:

PlatformConfig path
macOS~/Library/Application Support/ntrack/ntrack_config.json
Windows%APPDATA%\ntrack\ntrack_config.json
Linux~/.config/ntrack/ntrack_config.json

Example config file:

{
  "api_url": "http://localhost:8765",
  "api_key": "your-api-key-here"
}
💡

You can also seed the config via environment variables on first run — useful for automated deployments. See Environment Variables below.

Environment Variables

These are read on startup and only take effect if no config file exists yet (i.e. first run).

VariableDefaultDescription
NTRACK_API_URL http://localhost:8765 Base URL of the nwork backend
NTRACK_API_KEY empty API key for authentication
NTRACK_POLL_INTERVAL 5 Active window sample interval in seconds
NTRACK_REPORT_INTERVAL 60 How often to send a report to the backend (seconds)
NTRACK_DEVICE System hostname Device label included in reports

API Reference

ntrack communicates with a single nwork endpoint.

POST /api/v1/activity/report

Submits the daily activity report for the authenticated employee. ntrack calls this every NTRACK_REPORT_INTERVAL seconds.

Authentication: X-Api-Key: <api-key> request header.

Request body:

{
  "date":             "2026-04-11",          // required — ISO date (yyyy-MM-dd)
  "startTime":        "2026-04-11T08:03:00",  // first active timestamp of the day
  "endTime":          "2026-04-11T17:45:00",  // last active timestamp
  "activeMinutes":    372,
  "idleMinutes":      88,
  "apps": [
    { "name": "Code", "tab": null, "minutes": 210 },
    { "name": "Chrome", "tab": "github.com", "minutes": 62 }
  ],
  "hourlyBreakdown": [
    {
      "hour": 9,
      "apps": [
        { "name": "Code", "tab": null, "minutes": 45 }
      ]
    }
  ],
  "sessions": [
    {
      "name":  "Chrome",
      "tab":   "github.com",        // null for non-browser apps
      "start": "2026-04-11T09:15:00",
      "end":   "2026-04-11T09:42:00"
    }
  ]
}

Success response 200 OK:

{
  "data": {
    "id": 42,
    "employeeId": 7,
    "employeeName": "Juan dela Cruz",
    "date": "2026-04-11",
    "activeMinutes": 372,
    "idleMinutes": 88,
    // ... apps, sessions, hourlyBreakdown echoed back
    "reportedAt": "2026-04-11T17:45:02"
  },
  "message": "Activity reported"
}

Error responses:

StatusCause
400date field missing or invalid format
401Missing or invalid X-Api-Key
403Key exists but does not have reporting permission
💡

If a report for the same date already exists, the backend upserts — it updates the existing record rather than creating a duplicate.

Tray Menu

ItemDescription
View LogsOpens a window showing real-time tracking status and recent report history
SettingsConfigure API URL and API Key
QuitStop ntrack and remove it from the tray

The tray icon color indicates the current connection state:

  • Orange — connecting / first launch, not yet configured
  • Green — connected, reports sending successfully
  • Red — error or disconnected (check API URL and key)

Building from Source

macOS (.app)

chmod +x build.sh
./build.sh

Output: dist/ntrack.app. Optionally wraps into a .dmg if create-dmg is installed (brew install create-dmg).

Windows (.exe)

.\build.ps1

Output: dist\ntrack\ntrack.exe. Requires PyInstaller (installed via requirements.txt).

Running tests

pytest -v
