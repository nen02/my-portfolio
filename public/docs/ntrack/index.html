Overview

ntrack is a lightweight system-tray agent that monitors which applications and browser tabs are active on a desktop and periodically sends a daily activity summary to a backend service over HTTP. It is designed to run silently in the background with no user interaction required after initial setup.

ℹ️

ntrack is backend-agnostic. It sends a JSON payload to a single HTTP endpoint using an API key header. Any backend — regardless of language or framework — can receive its data as long as it implements the API contract below.

What ntrack tracks per day:

  • Total active and idle time (minutes)
  • Per-app usage (app name + browser domain, minutes)
  • Hourly breakdown of app usage
  • Session intervals (app, tab, start, end)

Requirements

RequirementNotes
Python 3.11+Only needed when running from source or building
macOS, Windows, or LinuxAll three platforms are supported

On macOS, ntrack requires Accessibility permission to detect the active window. You will be prompted on first launch — grant it in System Settings → Privacy & Security → Accessibility.

API Contract

ntrack sends one HTTP request to your backend every NTRACK_REPORT_INTERVAL seconds (default: 60). Your backend must implement this single endpoint.

POST /api/v1/activity/report

Submits the day's activity snapshot for the authenticated user. Called repeatedly throughout the day — implement it as an upsert keyed on (user, date) so repeated calls update rather than duplicate the record.

Authentication: ntrack sends the API key in the X-Api-Key request header. Your backend is responsible for validating it and resolving it to a user.

Request body:

{
  "date":             "2026-04-11",          // required — ISO date (yyyy-MM-dd)
  "startTime":        "2026-04-11T08:03:00",  // first active timestamp of the day
  "endTime":          "2026-04-11T17:45:00",  // last active timestamp
  "activeMinutes":    372,
  "idleMinutes":      88,
  "apps": [
    { "name": "Code",   "tab": null,          "minutes": 210 },
    { "name": "Chrome", "tab": "github.com",  "minutes": 62 }
  ],
  "hourlyBreakdown": [
    {
      "hour": 9,
      "apps": [ { "name": "Code", "tab": null, "minutes": 45 } ]
    }
  ],
  "sessions": [
    {
      "name":  "Chrome",
      "tab":   "github.com",        // null for non-browser apps
      "start": "2026-04-11T09:15:00",
      "end":   "2026-04-11T09:42:00"
    }
  ]
}

Expected response — 200 OK with any JSON body (ntrack ignores the body on success).

Error responses ntrack handles:

StatusBehavior
200Report accepted — tray turns green
4xx / 5xxReport queued locally in SQLite and retried on the next interval
Network errorSame as above — tray turns red
💡

All fields except date are optional. A minimal backend only needs to store date, activeMinutes, and apps to be useful.

Backend Examples

Below are minimal examples of implementing the endpoint in common stacks. These are starting points — add persistence, authentication, and error handling to suit your needs.

Node.js / Express

const express = require('express');
const app = express();
app.use(express.json());

const API_KEYS = new Set(['your-secret-key']);

app.post('/api/v1/activity/report', (req, res) => {
  const key = req.headers['x-api-key'];
  if (!API_KEYS.has(key)) return res.status(401).json({ error: 'Unauthorized' });

  const { date, activeMinutes, idleMinutes, apps, sessions } = req.body;
  if (!date) return res.status(400).json({ error: 'date is required' });

  // persist report here (DB upsert keyed on key + date)
  console.log(`Report for ${date}: ${activeMinutes} active mins`);
  res.json({ message: 'Activity reported' });
});

app.listen(8765);

Python / FastAPI

from fastapi import FastAPI, Header, HTTPException
from pydantic import BaseModel
from typing import Optional, List
from datetime import date

app = FastAPI()
API_KEYS = {"your-secret-key"}

class AppUsage(BaseModel):
    name: str
    tab: Optional[str] = None
    minutes: int

class ActivityReport(BaseModel):
    date: date
    activeMinutes: Optional[int] = None
    idleMinutes: Optional[int] = None
    apps: Optional[List[AppUsage]] = []

@app.post("/api/v1/activity/report")
def report(body: ActivityReport, x_api_key: str = Header(...)):
    if x_api_key not in API_KEYS:
        raise HTTPException(status_code=401)
    # persist report here (upsert keyed on key + date)
    return {"message": "Activity reported"}

Go / net/http

package main

import (
    "encoding/json"; "net/http"
)

var apiKeys = map[string]bool{"your-secret-key": true}

func reportHandler(w http.ResponseWriter, r *http.Request) {
    if !apiKeys[r.Header.Get("X-Api-Key")] {
        http.Error(w, "Unauthorized", 401); return
    }
    var body map[string]any
    json.NewDecoder(r.Body).Decode(&body)
    // persist body["date"], body["activeMinutes"], body["apps"] ...
    json.NewEncoder(w).Encode(map[string]string{"message": "Activity reported"})
}

func main() {
    http.HandleFunc("/api/v1/activity/report", reportHandler)
    http.ListenAndServe(":8765", nil)
}
💡

The endpoint path /api/v1/activity/report is the default. If your backend uses a different path, set NTRACK_API_URL to the base URL and the path will be appended automatically — or point it directly to your server root and rename the route to match.

Installing ntrack

Option A — Download a pre-built binary

Download the latest release for your platform from the GitHub Releases page.

PlatformFileLocation after install
macOSntrack.dmgDrag ntrack.app to /Applications
Windowsntrack-setup.exeInstalls to %LOCALAPPDATA%\ntrack
⚠️

macOS Gatekeeper: If the app is blocked, right-click → Open, or run: xattr -cr /Applications/ntrack.app

Option B — Run from source

git clone https://github.com/nen02/ntrack-app.git
cd ntrack-app

# Create virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Run
python main.py

Configuration

On first launch, ntrack starts in a disconnected state. Open the tray icon and go to Settings to enter:

  • API URL — base URL of your nwork backend (e.g. http://192.168.1.10:8765)
  • API Key — the key generated in the nwork web app

Config is saved to a persistent directory that survives app updates:

PlatformConfig path
macOS~/Library/Application Support/ntrack/ntrack_config.json
Windows%APPDATA%\ntrack\ntrack_config.json
Linux~/.config/ntrack/ntrack_config.json

Example config file:

{
  "api_url": "http://localhost:8765",
  "api_key": "your-api-key-here"
}
💡

You can also seed the config via environment variables on first run — useful for automated deployments. See Environment Variables below.

Environment Variables

These are read on startup and only take effect if no config file exists yet (i.e. first run).

VariableDefaultDescription
NTRACK_API_URL http://localhost:8765 Base URL of the nwork backend
NTRACK_API_KEY empty API key for authentication
NTRACK_POLL_INTERVAL 5 Active window sample interval in seconds
NTRACK_REPORT_INTERVAL 60 How often to send a report to the backend (seconds)
NTRACK_DEVICE System hostname Device label included in reports

Tray Menu

ItemDescription
View LogsOpens a window showing real-time tracking status and recent report history
SettingsConfigure API URL and API Key
QuitStop ntrack and remove it from the tray

The tray icon color indicates the current connection state:

  • Orange — connecting / first launch, not yet configured
  • Green — connected, reports sending successfully
  • Red — error or disconnected (check API URL and key)
